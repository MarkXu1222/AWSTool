## High-level view

区域发现只使用 payer 凭证执行一次 `DescribeRegions`，随后把这组区域展开到每一个 ACTIVE 成员账户。可选区域的启用状态是账户级的，成员没有启用 payer 已启用的区域时，StackSet 不可能满足当前矩阵。

Repair 一经提交就立即返回并重置 `phaseStartedAt`，90 分钟超时只在“本轮没有提交 repair”时检查。持续失败目标因此会被无限提交 `UpdateStackInstances`，任务既不会完成，也不会进入可人工重试的 failed 状态。

当前 tracked diff 中 `index.ts` 和 `routes/aws.ts` 都导入 `./tag-onboarding`，但该实现文件仍是 untracked。由当前 diff 创建的提交、CI checkout 或 EC2 `git pull` 都不会包含它。

### 成员账户的可选区域差异会制造不可完成的 StackSet 矩阵（confirmed）

`runDeployReIndexes` 调用 `getEnabledRegions(payerAccountId)`，后者仅使用 payer 凭证执行 `DescribeRegions`（`web/server/tag-onboarding.ts:208-216`，`web/server/tag-compliance.ts:1263-1272`）。状态检查随后把同一组 `requiredRegions` 与所有 ACTIVE 成员账户做笛卡尔积（`web/server/tag-compliance.ts:1340-1343`）。对于 opt-in 区域，payer 已启用而成员未启用时，该成员的 StackSet 实例无法成功，矩阵却永久要求它达到 `CURRENT/SUCCEEDED`。

Repair 会继续对不可部署的 account-region 目标发起更新，S3 upsert 永远不会执行。目标矩阵应基于每个成员账户真实启用的区域构造，或在下发前显式统一开启区域。

### repair 提交路径永久绕过阶段超时（confirmed）

`runWaitStackSets` 在 `repair.submitted` 为 true 时调用 `waitForRetry(..., true)` 并直接返回；这个 `true` 会把 `phaseStartedAt` 重置为当前时间（`web/server/tag-onboarding.ts:121-129,237-240`）。90 分钟检查位于提前返回之后（`web/server/tag-onboarding.ts:241-244`）。只要失败或缺失目标持续存在，repair 每轮都能再次提交 Create/Update 操作，任务就永久停留在 `waiting_retry`。

Repair 应共享不可重置的阶段 deadline，并为目标或批次记录有界尝试次数；达到期限或重复失败上限后必须转为 `failed`。

### runner 未进入版本控制会使部署缺模块（confirmed）

`web/server/tag-onboarding.ts` 当前是 `??` 未跟踪文件，而 tracked 变更已在 `web/server/index.ts` 和 `web/server/routes/aws.ts` 中静态导入它。本地构建通过只是因为该文件仍存在于工作区；从当前 Git diff 生成的提交、CI checkout 或 EC2 `git pull` 都会缺少模块。

部署前必须显式加入 `web/server/tag-onboarding.ts`，不要同时加入同批出现的临时脚本、`semantic-review/` 或其它无关未跟踪内容。
