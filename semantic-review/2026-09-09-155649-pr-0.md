# Cost Explorer removal with operations-only Dashboard and expanded Cleanup scanning

The change removes Cost Explorer from AWSTool Web’s runtime surface while retaining Dashboard operational counters, Billing PDF jobs, and resource cleanup. The four prior-round fixes are present: Cleanup derives 17 default plus enabled opt-in regions and falls back to all 34 known regions without `region_data`; pnpm follows the canonical npm lock; paid-query URLs remain only as historical audit matchers; and Dashboard cache helpers are gone with the legacy field documented as unread. One release concern remains: expanded all-region results are merged by keys that omit region, so legitimate regional resources can disappear from Cleanup.

**Watch for: confirmed — same-named Lambda functions overwrite one another during 17/34-region aggregation, making “全部可用区域” incomplete.**

**Verdict**: NEEDS_CHANGES

## High-level view

Cost Explorer is removed from service methods, Express routes, client calls, UI, Dashboard scheduling, IAM policy fragments, and dependency metadata. The only old billing-query paths left are audit presentation rules for historical records; no router mounts them. Billing PDF submit/list/status/cancel/download endpoints and their authorization boundary remain mounted.

`/dashboard/summary` now returns role-health, pending-quota, and departed-account counts without calling billing APIs or touching `dashboard_cache`. Account, Case, and connection cards remain sourced through their existing non-CE calls.

Cleanup’s region discovery follows the intended policy: 17 default regions are always included, cached `ENABLED` opt-in regions are added, and a missing account cache entry falls back to all 34 known regions. Its aggregation stage is still region-blind for regional resources, so the broader scan does not guarantee that every discovered resource reaches the table.

All three dependency manifests are free of the Cost Explorer package. Server TypeScript checking, client production bundling, and `git diff --check` pass; the build reports only the existing large-chunk warning.

## Cost Explorer is absent from the runtime and trust boundary

`aws-service.ts` no longer imports the CE SDK or exposes cost-query methods, account detail no longer performs a hidden CE request, and `routes/aws.ts` no longer mounts `/billing/by-account`, `/billing/by-service/:accountId`, or `/billing/breakdown/:accountId`. Client calls, scheduled cost-cache refreshes, `ce:Get*` policy actions, and package/lock entries are also gone.

The exact historical URL mappings in `audit-presentation.ts`, including breakdown, only format stored logs. Keeping both `账单分析` and `账单导出` colors preserves old records without reopening a network path. PDF job routes continue through `requireBillingAccess`, owner/admin checks, and the persistent job runner.

## Expanded region discovery can collapse distinct regional resources

`availableRegions` at `Cleanup.tsx:188` implements the requested selection policy, and all-region mode consumes it at `Cleanup.tsx:207`. At `Cleanup.tsx:223`, however, every response is inserted as `merged.set(r.key, ...)` regardless of source region. The backend defines Lambda keys as `Lambda:${FunctionName}` at `aws-service.ts:1408`; EC2 and EBS keys at `aws-service.ts:1330` and `aws-service.ts:1358` are also not explicitly region-qualified.

If `Lambda:processor` exists in two enabled regions, the later response replaces the earlier row and `_region`. The hidden function cannot be selected or deleted from that result. Regional rows need a region-qualified aggregation key, while S3 and IAM should remain globally keyed because their responses repeat on every regional scan.

**Not tested — confirmed:** two regions returning the same Lambda name, global IAM/S3 duplication across 34 responses, enabled opt-in cache entries, and an account absent from `region_data`.

## Dashboard cache removal is complete

The old cache reader/writer, refresh helper, startup refresh, and two-hour interval are removed together, leaving any production `dashboard_cache` value inert. The client drops cost cards and rankings while retaining account totals, recent Case counts, organization connection status, role issues, pending quotas, recent joins, and departed-account counts.

## Dependency and build verification

`package.json`, `package-lock.json`, and `pnpm-lock.yaml` contain no `client-cost-explorer`. The pnpm importer now includes the dependencies missing in the previous pass, with the reviewed AWS SDK and Puppeteer versions aligned to the canonical npm resolution.

`tsc -p server/tsconfig.json --noEmit`, a Vite production build redirected to `/tmp/awstool-semantic-review-v2`, and `git diff --check main -- . ':(exclude).gitignore'` all passed. The pre-existing local `node_modules` has an extraneous CE directory, but no checked-in manifest or lock references it, so it is not part of a clean/frozen installation.
