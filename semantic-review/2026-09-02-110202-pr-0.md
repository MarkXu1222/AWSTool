# Bounded local Excel account import

The billing export dialog now accepts local `.xlsx` files, extracts AWS account IDs across worksheets, and restricts selection to accounts known by the platform. The previous unbounded pre-parse decompression path is guarded by central-directory validation on the main thread and actual streamed-output accounting inside a dedicated Worker before workbook parsing. Worker ownership, timeout, and cleanup bound parsing away from the UI thread. No confirmed High or Medium issue remains in the requested scope.

Watch for: None — no **confirmed** High/Medium concerns.

**Verdict**: APPROVED

## High-level view

The archive trust boundary is enforced twice. Main-thread metadata work is bounded by a 5 MiB file and 1,000 entries; the Worker then distrusts declared ZIP sizes and counts actual decompressed output before `readXlsxFile()` can allocate the workbook representation.

Parsing and XML traversal run outside the UI thread. The transferred `ArrayBuffer`, settled guard, 20-second deadline, and terminal cleanup paths bound the outer Worker's lifetime, and production bundling emits it as a separate asset.

Extracted IDs are deduplicated and intersected with the loaded platform account list. A zero-match file preserves the existing selection; a partial match replaces it with the matched subset and reports rejected IDs.

## ZIP bomb containment before workbook parsing

The main-thread scan rejects malformed or multi-disk archives, ZIP64 sentinels, encrypted entries, excessive entry counts, excessive declared expansion, and archives missing mandatory workbook parts. Both input bytes and directory iterations are bounded, so preflight does not recreate the material UI-thread blocking risk it is intended to prevent.

Declared sizes are not authoritative. `verifyActualUncompressedSizes()` streams stored and deflated local entries through `fflate`, counts each output chunk, and throws when one entry exceeds 12 MiB or aggregate output exceeds 24 MiB. It completes before `readXlsxFile(event.data)`, closing the prior zip-bomb path.

## Worker isolation and normal workbook compatibility

The main thread transfers rather than copies the input buffer and terminates the Worker after success, reported failure, runtime error, or timeout. `read-excel-file@9.3.10` accepts `ArrayBuffer` and returns all worksheets, matching the worker loop; its nested blob workers are permitted because this deployment has Helmet CSP disabled. The production build emitted `account-import.worker-D_kN50Pi.js`, confirming the module Worker dependency graph bundles.

The structural checks retain standard XLSX behavior: `[Content_Types].xml` and `xl/workbook.xml` are required package parts, and ordinary stored/deflated entries are supported. ZIP64, encrypted, split, or limit-exceeding workbooks are deliberately rejected rather than partially parsed.

## Account selection boundary

String cells accept 12 digits at digit boundaries, numeric cells accept safe 12-digit integers, and results are deduplicated before platform matching. The platform-account intersection prevents workbook content from selecting unknown IDs. The 50,000-cell limit spans all worksheets; leading-zero IDs must be text because numeric Excel cells cannot preserve those zeros, which the dialog discloses.

## Validation performed

`npm run build` passed, covering the Vite production bundle and server TypeScript check. Dependency manifests pin `fflate` to `0.8.3` and `read-excel-file` to `9.3.10`.
