## Resource-family gaps 关闭 covered-model 假 clean

`RESOURCE_FAMILY_GAPS` 明确列出 `dynamodb:backups-exports-imports`、`lambda:layer-versions-code-signing-configs` 和 `ec2:capacity-reservations-capacity-blocks-dedicated-hosts-fleets-spot-requests`（`scripts/cleanup.py:71-81`）。`runtime_coverage_gaps()` 无条件合并这些 family gaps、`KNOWN_COVERAGE_GAPS` 及 `get_available_services() - COVERED_BOTOCORE_SERVICE_MODELS` 产生的 `unclassified-service-model:*`（`scripts/cleanup.py:911-928`）。

`coverage_complete` 还要求 coverage key 无重复、实际 key 与 enabled regions × `REGIONAL_SCANNER_IDS` 加全部 `GLOBAL_SCANNER_IDS` 完全相等，并且每项成功（`scripts/cleanup.py:333-352`）；regional/global scanner tuple 也分别与 manifest 做等值检查。离线 smoke 在“available services 恰好等于 covered models”的最宽松场景下验证，三个指定 family gap 仍存在且 `coverage_complete == false`。

## 完整 inventory 使 protected-KMS guard 可达

`command_nuke` 调用 `delete_round(deletable, inventory_context=inventory.resources)`，把未过滤 inventory 与执行列表分开传入（`scripts/cleanup.py:2944-2974`）。`protected_service_resources_remain` 因而能看到 `protected_residual`，并在 KMS item 到达 `_delete_KMSKey` 前返回 dependency waiting（`scripts/cleanup.py:2096-2129`）。这是全仓唯一调用点；无 AWS smoke 用 protected CloudFormation stack + enabled KMS key 验证结果为 waiting。

protected stack 及其非 IAM 后代不会成为 allowed residual；verify/nuke final 仅豁免 access-chain IAM、精确 default-VPC baseline 和已处于 pending-deletion 的 KMS，其他 protected 对象持续阻止 complete（`scripts/cleanup.py:1888-1950, 2853-2863, 2998-3008`）。

## 写入口、目标身份与访问链保持 fail-closed

scanner 与 payer cost 路径只使用 assume-role、list/get/describe 调用；mutation verb 的首次静态命中是 `ResourceDeleter._delete_CloudFormationStack`（`scripts/cleanup.py:2172`）。`nuke` 在建 scanner 前、每轮和 final verify 前验证映射 payer 是 live management account、目标是其 ACTIVE member且不是 management account，并再次断言目标 STS account（`scripts/cleanup.py:758-786, 2895-2929, 2995-2997`）。每轮的 `inventory.issues or not inventory.coverage_complete` 分支在 `delete_round` 前停止且 actions 为空（`scripts/cleanup.py:2929-2974`）。

preservation 覆盖默认及配置中的 child/admin/support role、service-linked role、相应 instance profile、customer-managed policy、permissions boundary 和含 protected role 的 CloudFormation parent/child closure（`scripts/cleanup.py:113-116, 261-271, 1242-1304, 1554-1596, 1755-1769`）。IAM deleter还会二次拒绝 preserved role 及仍附着于 preserved role 的 policy（`scripts/cleanup.py:2741-2743, 2780-2786`）。

## CFN ownership 与 scoped identity 未回归

非已删除的 mapped CloudFormation physical reference 必须在对应 global/stack region 精确匹配一个 inventory item；未知 type、零匹配、多匹配和多个 owner 都成为 blocking issue（`scripts/cleanup.py:1822-1892`）。EKS cluster/child、DynamoDB table、EventBridge rule 以 ARN 为 inventory ID并保留 parent/name alias；冲突 key 生成 `ConflictingResourceIdentity`，删除 API继续使用保存的 cluster、table name 或 event bus/name（`scripts/cleanup.py:1354-1425, 1864-1883, 2251-2286, 2305-2316`）。

## Async round budget 已覆盖 deadline

配置拒绝 `(max_rounds - 1) * wait_seconds < async_deadline_seconds` 的组合（`scripts/cleanup.py:2906-2922`）。deadline 从 async resource 首次进入 deletable inventory 时计时，有 current async 时不触发 `consecutive_no_progress`（`scripts/cleanup.py:2944-2989`）；上一轮轮数上限可早于 deadline 的问题已关闭。
