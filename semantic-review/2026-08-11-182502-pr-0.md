## High-level view

区域发现、部署与状态判定使用同一份持久化 `memberEnabledRegions`。Resource Explorer StackSet 接收成员+payer 区域并集，payer 管理账户直接创建索引时只使用 `payerEnabledRegions`；完成矩阵只为当前 ACTIVE 成员在其快照中实际启用的区域生成目标。

`wait_stacksets` 先读取 AWS 当前状态，再检查固定的 90 分钟 deadline；repair 和服务重启恢复均不改写 `phaseStartedAt`。因此 AWS 已完成的恢复任务不会因停机时间直接失败，持续未完成的任务也不能通过 repair 无限续期。

变更后的生产调用点签名一致，旧手工三参数调用由 `deployReIndexes` 的默认第四参数保持兼容。任务只有在精确 StackSet 矩阵、S3 关键字段回读和前置资源检查同时通过后才进入 `completed`。

### 区域快照与 StackSet 目标对称

`getMemberEnabledRegions` 分页取得 ACTIVE 成员，逐账户 AssumeRole 并调用 `DescribeRegions(AllRegions=true)`，结果在进入 `wait_stacksets` 前持久化。部署端将成员区域与 payer 区域合并为 StackSet 区域，同时把 payer 自身区域独立传给管理账户索引创建；状态端按每个成员自己的启用区域生成 expected keys。missing/failed targets 可按 StackSet、区域和账户批次 repair，根 OU 目标缺失也会重新绑定 required regions。

### Deadline、恢复与完成门槛

管理账户索引等待、StackSet 等待和最终 verify 均先读取当前状态，只在仍不满足时判断 deadline。重启只把持久化的 `running` 任务放回同一 phase，保留阶段产物和计时起点；部署、repair 与 S3 upsert 可重复进入。

`completeJob` 只从 verify 成功分支进入。verify 同时要求精确 StackSet 矩阵完成、S3 中 org/search role/view/tag value 精确匹配，以及 search role、OrgView 和 AutoTagger StackSet 前置检查通过。

### 调用签名与验证

新增 runner 调用均传入 `memberEnabledRegions`；旧 `/tag-compliance/re-indexes` 路由仍可依赖 `payerLocalRegions = localRegions` 默认值。`git diff --check main` 与 `npm run build` 通过，后者覆盖 Vite 生产构建和 `tsc -p server/tsconfig.json`；仅有非阻断的大 chunk 体积警告。
