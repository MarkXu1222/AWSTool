# Resource Explorer StackSet 精确目标与迁移

本次改动将默认区域根 OU 目标与 opt-in 区域账户交集拆分到两个本地索引 StackSet，并在旧宽泛目标迁移时保留现有资源。AWS SDK 命令与参数类型已通过生产构建，missing/`AlreadyExists` 的 retained index 也会回读验证。仍有一个边界条件破坏 future-account 保证：没有当前成员账户的组织可以在未建立任何 Resource Explorer 根目标时完成接入。Watch for: **confirmed Medium** — 首个后续加入该空组织的成员账户不会通过 AutoDeployment 获得聚合索引和默认区域本地索引。

**Verdict**: NEEDS_CHANGES

## High-level view

正常迁移路径符合目标模型：`RE_LOCAL_STACKSET` 只持有动态 `opt-in-not-required` 区域的根 OU 目标，`RE_SCOPED_LOCAL_STACKSET` 以 AutoDeployment=false + `INTERSECTION` 持有 opt-in 区域，旧额外根区域先用 `RetainStacks=true` 解绑，再由 repair 核验或补齐 scoped 覆盖。

空组织路径没有建立同样的拓扑。代码跳过两个 Resource Explorer 根目标，并因预期实例数为零直接判定所有定义完成，留下已启用 AutoDeployment、但没有 OU/region 作用域的 StackSet。

## 空组织会在缺少 future Resource Explorer 覆盖时完成

**Confirmed Medium.** `deployReIndexes` 在 `memberAccountIds.length === 0` 时跳过 Aggregator 操作（`web/server/tag-compliance.ts:1160`），本地区域又完全从当前成员区域派生（`web/server/tag-compliance.ts:1185-1195`）。因此空组织的 `RE_AGGREGATOR_STACKSET` 和 `RE_LOCAL_STACKSET` 都不会获得根 OU 目标。

状态模型同时在没有成员时清空 required/root-required regions（`web/server/tag-compliance.ts:1670-1691`），并仅凭 `requiredRegions` 为空就标记完成（`web/server/tag-compliance.ts:1900-1902`）。接入任务随后可以写入配置并成功结束；首个未来成员加入时，没有 Aggregator 或默认本地区域的根目标可供 AutoDeployment 执行。`AutoTaggerRole` 已采用可复用的正确模式：当前实例数为零时仍提交根 OU 目标。

应在空组织中仍将 `RE_AGGREGATOR_STACKSET` 绑定到默认聚合区，并将 `RE_LOCAL_STACKSET` 绑定到 payer 的 `defaultRegions`（排除聚合区）。完成判定即使 `expectedInstanceCount === 0`，也必须要求根目标和 StackSet 配置有效；只有逐账户实例检查可以为空。

Low: **confirmed** — 当前没有针对空组织或 retain-and-repair 迁移路径的自动化测试；本次验证仅覆盖生产构建和 SDK 命令可用性。
