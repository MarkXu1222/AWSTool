# MAP onboarding payer 区域诊断与失败详情展示

这组改动在 `deploy_re_indexes` 前比较 payer 与 ACTIVE 成员账户的区域状态，把不可自动恢复的前置条件持久化为结构化 failure，并在失败卡片中展示诊断与重试入口。区域差集、旧任务兼容、重试状态清理和完整区域覆盖没有发现行为错误。主要缺口是所有当前 `awsMessage` 都与 `reason` 相同，而 React 只在两者不同时展示“AWS 原始错误”，使新增的原始错误区块和复制入口不可达。

Watch for: **confirmed（中）** AWS 原始错误专属展示在当前失败路径中不可达；**confirmed（低）** 新区域矩阵与 failure 生命周期没有自动化测试；**confirmed（低）** MAP 修复 diff 混入账单导出持久化代码。

**Verdict**: NEEDS_CHANGES

## High-level view

`affectedAccountsByRegion` 按“ACTIVE 成员已启用、payer 未启用”构造，排除了 payer 和非 ACTIVE 账户。前置条件满足后仍使用完整区域并集部署，因此新增判断本身没有缩小目标覆盖。

failure 是可选持久化字段，旧任务回退到 `lastError`；手动重试、阶段推进、等待和重新执行都会清除旧诊断，当前阶段尝试次数也会重置。前端仅在 failed 状态并且 `manualRetryAllowed !== false` 时提供重试。

AWS SDK 格式化保留错误名、message 与 requestId，并逐区域汇总 payer 本地索引失败；但格式化文本最终同时写入 `reason` 和 `awsMessage`，触发前端去重并隐藏原始错误专属区块。

## AWS 原始错误被等值去重条件隐藏

`handleRunError` 的通用分支在 `web/server/tag-onboarding.ts:174-184` 把同一个 `message` 同时赋给 `failure.reason` 和 `failure.awsMessage`。两个自定义 payer 区域 failure 没有 `awsMessage`，其余永久错误和 AWS/API 错误都走通用分支，因此现有代码中只要 `awsMessage` 存在，它就与 `reason` 相等。

`web/client/src/pages/TagCompliance.tsx:709-715` 又要求 `awsMessage !== reason` 才渲染“AWS 原始错误”及复制控件。错误文本仍会出现在“具体原因”下，但无法实现独立原始错误展示，也无法区分操作员摘要和 AWS 原文。应给通用 failure 一个稳定的人类可读 `reason`、把格式化 AWS 文本仅放入 `awsMessage`，或移除前端等值隐藏条件。该问题为 **confirmed（中）**。

## 区域矩阵与 failure 生命周期缺少回归测试

项目没有测试脚本，也未找到 onboarding/tag compliance 测试。成员区域差集及账户归组、payer 聚合区域缺失、旧任务无 failure、自动重试到终态、手动重试清理和 UI gating 均未自动验证。应至少抽出区域差集/失败构造纯函数，并覆盖持久化与重试状态转换。该问题为 **confirmed（低）**。

## `db.ts` 混入独立账单导出持久化变更

`web/server/db.ts` 同时新增账单导出任务模型、队列约束、恢复和查询更新函数，与 payer 区域诊断没有调用关系，却扩大了发布和回滚面。应在提交或 PR 边界拆分这部分。该问题为 **confirmed（低）**。

`git diff --check`、服务端 `tsc --noEmit`、客户端 `tsc --noEmit` 和 Vite 生产构建均通过；构建仅有大 chunk 警告。未执行 AWS 集成测试，无法本地验证真实 opt-in 状态或 CloudFormation StackSet 的服务端拒绝文本。
