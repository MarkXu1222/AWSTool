# 账单导出永久历史与重复鉴权下载

本次变更把账单导出从 TTL 生命周期改为服务器永久历史：完成产物不再按 expiresAt 删除，任务元数据不再裁剪，启动阶段只清理明确未完成任务的临时目录。历史接口改为分页并默认 mine；管理员只有显式请求 all 才能查看全局记录，单任务详情和下载继续执行实时页面权限与 owner/admin 校验。前端增加当前用户历史列表、详情恢复和重复下载，同时保留旧 completed/expired 记录的兼容语义。README 与 project-context 对永久保留、磁盘监控和独立备份责任的描述与实现一致。

Watch for: 本轮未发现 **confirmed** High/Medium 问题。

**Verdict**: APPROVED

## High-level view

持久化边界已改为无隐式删除。新任务不再写 expiresAt，旧 completed 即使带有已过期 expiresAt 仍保持可下载；DB 不再淘汰历史，启动清理不会触碰 completed、expired 或 orphan 目录。

历史读取采用服务端分页。mine 是普通用户和管理员的默认范围，all 必须由管理员显式请求；列表、详情与下载均基于数据库中的当前用户权限，下载请求本身再次校验 owner/admin 后才打开 ZIP。

前端历史入口支持分页、详情和重复下载。旧 expired 继续展示为不可用，completed 下载前会重新读取服务端状态并向受保护端点发送当前 JWT。

## completed、expired 与 orphan 的保留边界

`runJob`、`toBillingExportJobView` 和 `getBillingExportDownload` 不再生成或执行 expiresAt。启动清理仅覆盖 cancelled、failed 和 interrupted，completed、legacy expired 及 orphan 目录不会被 runner 枚举删除；创建 job 时原有的 100 条终态历史裁剪也已移除。

旧 expired 仍拒绝下载。旧 completed 忽略 expiresAt；若实际文件确实不存在，记录会保留并转为 expired，而不是删除元数据。

## mine/all 分页与下载信任边界

scope 缺省为 mine，只有数据库当前角色为 admin 且显式 scope=all 才能列出全局历史。mine 优先匹配稳定 `createdByUserId`，仅迁移前缺少 ID 的记录回退用户名。

详情、取消和下载先由 `requireBillingAccess` 读取 DB 当前用户并核对 JWT userId/username，再执行 owner/admin 校验。ZIP 在鉴权通过后才打开，文件名和目录均有边界检查；客户端每次重复下载都携带当前 Bearer token，不使用可绕过鉴权的静态链接。
