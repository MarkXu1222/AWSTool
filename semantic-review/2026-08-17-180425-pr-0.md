## High-level view

CloudFormation ownership 对空 physical ID fail closed，`DELETE_COMPLETE` 是唯一可忽略状态；未知 Custom 类型没有 allowlist、provider identity 或 trusted marker 通道。

EventBridge 显式消费全部 `NextToken`，重复 token 失败。Lambda stale reference 只接受 `GetFunction` 的 NotFound，Event rule 要求每个已枚举 bus 的 `DescribeRule` 都返回 NotFound；非 NotFound 错误保持阻断。

Lambda Permission 必须由 processed template 的同 logical ID 指向同 stack 唯一活跃 Lambda，scanner 与 relationship pass 分别证明并复核 parent。Scanner manifest、删除顺序与 deleter method 的正向契约覆盖 35 个 scanner、83 个资源类型。

Nuke 在构造 deletable 前检查 issue 与 coverage；两条离线 trap 均保持零次 deleter 调用。Python 3.9 feature-version AST、boto3 1.42.68 模块导入和 `validate_runtime()` 通过，但本机只有 Python 3.13.7。

## 空 PhysicalResourceId 与 Custom reference 的 fail-closed 边界

`apply_resource_relationships()` 在类型映射前检查 physical ID；状态不是 `DELETE_COMPLETE` 时追加 `MissingPhysicalResourceId`（`scripts/cleanup.py:2127-2141`）。`Custom::Anything` + `CREATE_IN_PROGRESS` + 空 ID 的离线 case 精确得到该 issue；带 `provider-id` 时得到 `UnsupportedCloudFormationType`。源码与两张 CFN map 均无 Custom、Quick Setup、template hash、service token 或 provider ARN 信任旁路。

## EventBridge absent proof 与 Permission parent 的双重证明

`list_event_bus_names()` 显式消费 `NextToken` 并拒绝重复 token（`scripts/cleanup.py:959-979`）。三页 fake client 的请求序列为无 token、`t1`、`t2`；inventory 与 stale probe 共用该 helper。

Stale proof 只为 Lambda function 和 Event rule 提供服务级证明（`scripts/cleanup.py:1361-1388`）。Lambda 调用 `GetFunction`；Event rule 对分页得到的 custom buses 与 default 逐一调用 `DescribeRule`。全部 NotFound 才写入 `confirmed_absent_by_api`，任一 AccessDenied 都让 scanner 失败。

Permission 只接受 processed template 中同 logical ID 的 `AWS::Lambda::Permission`，其 `FunctionName` 必须以 `Ref` 或 `Fn::GetAtt ... Arn` 指向同 stack 唯一活跃 Lambda（`scripts/cleanup.py:1417-1473`）。精确 parent 通过两层校验；`Ref: OtherFn` 生成 `UnprovenStackManagedChild`。

## Scanner/deleter contract 与 nuke 零写门禁

`validate_runtime()` 校验 scanner/manifest 完全对应、CFN target 已声明、每个自动类型都有删除顺序和 `_delete_<Type>` method（`scripts/cleanup.py:700-726`）。35 个 scanner、83 个类型全部通过；Resource Explorer 与 SSM 的本地 botocore 1.42.68 operation shape 和 paginator model 匹配。

`command_nuke()` 在每轮 scan 后、计算 deletable 前执行 issue/coverage gate（`scripts/cleanup.py:3299-3334`）。注入 blocking issue 与 coverage gap 均得到 `blocking_scan_or_coverage_issues`、空 actions、零 deleter 调用；final completion 也要求 issue 为空且 coverage complete（`scripts/cleanup.py:3383-3394`）。

## 尚未固化的验证边界

**[Medium][confirmed]** 仓库没有 cleanup 专用测试文件；本轮一次性离线 harness 覆盖了上述安全不变量。Python 3.9 AST 通过，但缺少真实 3.9 二进制验证，应由持久化测试与 3.9 CI matrix 接管。

**[Low][confirmed]** `get_template(TemplateStage="Processed")` 返回字符串时只执行 `json.loads`（`scripts/cleanup.py:1419-1434`）。合法 YAML 会安全阻断而非误删，但形成可用性缺口。
