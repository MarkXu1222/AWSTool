# Resource Explorer StackSet 区域覆盖最终复审

本轮只复核上一轮区域覆盖问题的修复闭环。新任务的成员区域计算、零成员完成语义、旧任务参数过滤、顶层 `OUTDATED` / `INOPERABLE` 优先级，以及共同区域与 partial opt-in 区域的 repair 分流已经对齐。当前仍有一个迁移场景未闭环：旧实现曾把所有本地区域绑定到根 OU，新状态检查会忽略不再需要的绑定，却不会撤销它们。Watch for: **[confirmed][Medium]** 历史根 OU 自动部署目标可在状态显示完成后继续影响未来账户。

**Verdict**: NEEDS_CHANGES

## High-level view

部署入口现在以成员账户区域矩阵为准；仅所有成员共同启用的本地区域使用根 OU `NONE`，partial opt-in 缺口使用 `INTERSECTION`。状态检查会过滤旧任务中的 payer-only/失效区域，零成员不会要求成员 StackSet，三个状态读取点也统一让顶层 `OUTDATED` / `INOPERABLE` 优先。

剩余缺口位于 StackSet 的持久化部署目标，而非当前任务参数。基线实现曾对每个本地区域执行根 OU 部署；当前实现只验证所需根区域存在，没有识别或撤销多余根区域，因而无法把历史宽泛目标收敛为新的精确目标集合。

## 历史根 OU 自动部署目标未被收敛

**[confirmed][Medium]** 基线的本地索引部署对 `localRegions` 整体使用根 OU 目标。新状态路径在 `web/server/tag-compliance.ts:1617-1634` 读取这些目标后，只判断 `rootRequiredRegions` 是否全部存在；额外根区域不进入 `configurationValid`、missing/failed targets 或完成判定。`repairOnboardingStackSetCoverage` 也只有创建根目标和精确补建/更新，没有删除或替换旧目标的路径。

StackSet 仍启用 AutoDeployment，所以旧 partial opt-in 或 payer-only 区域的根 OU 目标会继续针对后来加入组织的账户发起部署，同时当前检查可报告 `complete: true`。新请求不会再制造这类过度部署，但从旧版本升级的组织仍未闭环，幂等性也只覆盖期望集合增加或重试，不覆盖期望集合缩减。

修复需要把实际根 OU 区域与 `rootRequiredRegions` 做双向 reconciliation：补建缺失目标，安全撤销或迁移额外目标，并保留 partial 区域中合法成员的索引；额外目标清理完成前不能返回 complete。

## 迁移路径尚无回归测试

**[confirmed][Low]** `npm run build` 已通过 Vite production build 与 server TypeScript 编译，相关文件的 `git diff --check` 也通过；但仓库没有覆盖旧根目标收敛的自动化测试。应至少以 mock CloudFormation 响应验证额外 root region 会阻止完成并进入清理路径，同时合法的 partial `INTERSECTION` 目标不被删除。
