# 账单导出永久历史与重复下载

0.14.1 将账单导出从 TTL 生命周期改为服务器永久保留：completed ZIP 不再按 `expiresAt` 失效，job 元数据不再裁剪，runner 也不再自动删除 completed、legacy expired 或 orphan 目录。历史 API 增加分页和显式作用域，默认 `mine`，只有 admin 显式请求 `scope=all` 才能列出全局记录。前端新增历史列表、详情入口和重复鉴权下载，同时保持旧 expired 记录不可下载。版本与运维文档同步到 0.14.1，staged diff 未混入 MAP、account lifecycle、restricted 或 payer 行为。

Watch for: 无 confirmed High/Medium 问题。

**Verdict**: APPROVED

## High-level view

持久化边界同时覆盖文件与元数据。新 completed job 不再写入有效期，视图和下载路径忽略旧 `expiresAt`，创建 job 时不再执行 100 条终态裁剪；启动清理仅处理 cancelled、failed、interrupted 半成品。

历史读取默认限定当前 owner。非 admin 请求 `all` 会被拒绝，admin 也必须显式传入 `all`；单 job 详情、取消和下载继续按稳定 user ID 校验 owner，admin 保留既有跨 owner 访问能力。

旧 completed 即使带有过期 `expiresAt` 也可下载，旧 expired 仍不可下载，实际文件缺失则将 completed 更新为 expired 而不删除元数据。前端固定以 `mine` 恢复最近任务和加载历史分页，并在详情或下载前重新请求鉴权端点。

## completed、expired 与 orphan 的保留边界

周期 sweeper、TTL 配置、到期判断和 orphan 目录扫描均从 runner 中移除。成功路径清空 `expiresAt`；completed、legacy expired 和 orphan 不进入启动清理集合，下载文件缺失时只将记录更新为 expired。cancelled、failed、interrupted 的失败半成品仍会清理，不扩大永久保留范围。

## 永久元数据与 owner 分页

创建 job 后不再把非活跃终态裁剪到最近 100 条。分页先按 owner/global 范围过滤，再按创建时间倒序切片，并返回 total、page、limit、totalPages 与 scope。

DB 函数和 HTTP 路由均默认 `mine`。`scope=all` 要求显式参数和数据库当前 admin 角色；详情和下载仍经过实时 billing 页面权限守卫，并使用稳定 `createdByUserId`，仅旧记录缺少该字段时回退用户名。

## 历史详情与重复鉴权下载

账单页新增 mine 范围历史弹窗，展示状态、任务数、结果和 ZIP 大小。详情会重新请求单 job 并复用现有任务面板；下载先选择保存位置，再刷新 job 状态并调用鉴权下载端点。旧 expired 禁用下载；文件丢失返回 410 后，前端同步将对应历史项标为不可用。

## 发布闭包与变更边界

`APP_VERSION`、README 当前版本和项目上下文均更新为 0.14.1。文档移除 TTL 环境变量和 24 小时说明，补充永久保留、磁盘监控与备份要求。staged 文件只涉及账单 job、账单前端/API、版本和对应文档，没有 MAP、账户生命周期、restricted 或 payer 业务改动。

## 验证证据

`git diff --cached --check` 通过；index 快照检索确认 TTL/sweeper 不再被账单实现引用，`billing_export_jobs` 不再存在历史裁剪赋值。用户提供的 staged-only `npm ci`/build、105 条 DB smoke 和 0.14.1 bundle 验证均已通过。本次判断未使用未暂存工作区。
