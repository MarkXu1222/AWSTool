# Bounded AWS client lifecycles and quota-value preservation

The scoped changes give temporary STS, Service Quotas, and scheduled Account clients deterministic teardown, attach abort signals to operation deadlines, and bound regional quota fan-out. Support-role availability now caches only definitive access denials, while connection probing shares one eight-second budget across both STS phases. Current quota enrichment retains account-scoped historical values when live reads fail, and the scheduler plus all three manual sync paths consume that result. No behavioral defects remain in the reviewed diff.

## High-level view

There are 13 `new STSClient` sites, not the stated 14. All 13 use `withAwsClient`; their sends use the `withAbortTimeout` signal, and no `const sts = new STSClient` remains.

The support-role cache now admits only `AccessDenied` and `AccessDeniedException`, leaving abort, throttling, credential, and transport failures retryable. `testConnection` measures payer-role elapsed time and assigns only the remainder of the eight-second allowance to identity lookup.

Regional quota work uses six draining workers. All six Service Quotas client sites and the scheduler Account client are destroyed after their sends settle, and their temporary operation timers are cleared on every exit path.

Historical current values are filtered by account and keyed by request ID. Live values take precedence, the scheduler has an additional null-safe fallback before persistence, and all three manual sync routes call enrichment.

## STS deadlines do not outlive client ownership

The 13 wrapped STS sites cover support-role and payer assumptions, account fallback, temporary admin credentials, AssumeRoot, connection probes, strict console roles, OAAR, and payer console sessions. `withAbortTimeout` clears its timer after the send settles, then `withAwsClient` destroys the client. In `testConnection`, fresh payer assumption can consume part of the eight-second budget; `GetCallerIdentity` receives only `8000 - elapsed` milliseconds.

## Regional workers drain before teardown

`mapWithConcurrency` limits active regions to six and waits on all workers before returning or propagating a rejection. Bedrock listing, quota-history listing, and enrichment own one timer and Service Quotas client per active region; paginated listing and quota increases use the shared wrappers. Scheduler region scans similarly wait for every Account send under one account-level abort controller before clearing the timer and destroying the client. The long-lived startup timers and intervals are pre-existing scheduler ownership and are outside this temporary-operation lifecycle.

## Failed enrichment cannot erase a known quota value

`enrichCurrentValues` builds prior history only from records whose `account_id` matches, then indexes by request ID. Its nullish order is live AWS value, incoming `_currentValue`, persisted same-account value, then null, preserving valid zeroes as well as older values after timeout or request failure. Scheduler persists `_currentValue ?? prev.current_value ?? null`; repository call-site inspection found the scheduler plus exactly three manual route invocations, each persisting enriched `_currentValue`.
