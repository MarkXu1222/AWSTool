# 持久化账单 PDF 后台 job 与可恢复下载

这组暂存变更把同步账单导出替换为持久化后台 job，覆盖进度、失败原因、取消、重启语义、TTL 下载与前端恢复。编排集中在单实例 runner，抓取固定使用只读 support 会话，并对 Chrome/zip 设置有界清理。路由实时校验 billing 权限，再以稳定 user ID 执行 owner/admin 授权；轮询降噪，提交、取消和下载显式审计。版本、文档、忽略规则和 Nginx 流式超时也同步更新。

Watch for: 本轮仅报告 confirmed High/Medium 阻断问题；未发现此级别问题。

**Verdict**: APPROVED

## High-level view

job 元数据写入现有 JSON 数据库，runner 串行领取 job、在 job 内有界并发。重启后 queued 继续排队，running/cancelling 明确终结为 interrupted，不会伪恢复失去进程上下文的工作。

所有 job 端点实时检查 billing 页面权限；新任务绑定稳定用户 ID，单任务状态、取消和下载再校验 owner/admin。导出器固定调用 `getConsoleSigninUrl(..., 'support')`，没有恢复旧的 `auto` 管理员回退。

完成产物保留到 TTL，重复下载每次重新鉴权，并以文件描述符和 lease 防止清理器删除传输中的文件。取消和停机共用 AbortSignal 与 Chrome/zip 有界收尾，无法确认进程退出时 runner 会暂停后续队列。

客户端与服务端使用同一组 `/billing/export-jobs` 契约。审计展示、0.14.0、`data/exports/` 忽略、Nginx 10 分钟流式窗口及运行依赖文档均在 staged 闭包内。

## 重启、取消与进程隔离边界

`billing_export_jobs` 持久化 owner、输入、阶段、计数、逐项结果、失败原因和产物元数据。runner 通过 localhost 独占端口拒绝第二个 Node/PM2 实例；恢复时只保留 queued，并把 running/cancelling 终结为 interrupted。取消会停止 worker 领取新任务并等待收尾；Chrome 和 zip 的 graceful→TERM→KILL 最终仍无法确认退出时，会抛出专用清理错误并冻结 runner。SIGTERM/SIGINT 同时停止 HTTP 接入和活动导出，整体受 30 秒 deadline 约束。

## support 会话、owner 授权与下载 lease

`requireBillingAccess` 从数据库读取当前页面权限，不依赖可能过期的 JWT 角色。新 job 强制写入 `createdByUserId`，用户名回退仅覆盖迁移前记录；状态、取消和下载要求 owner 或 admin。成员账户抓取不回退 OAAR/admin；payer 仅沿用既有 role/tool + ReadOnlyAccess session policy。下载重新检查 completed/TTL 后打开只读文件描述符并持有 lease，因此 TTL 内可重复下载，清理器也不会删除活动流。

## 前后端、审计与验证闭包

前端支持 202 提交、owner active job 恢复、轮询退避、取消、失败明细和流式保存；无 File System Access API 时把内存回退限制为 128 MiB。旧 `/billing/export-invoices` 在 staged 索引中无残留，四个显式审计动作均有展示映射，状态轮询被降噪。审查只使用 `git diff --cached`、`git show :path` 和 `git grep --cached`；Git index 隔离快照通过 `npm run build`（Vite + 全量 server TypeScript），编译后的 runner 也在独立 DB、输出目录和锁端口下通过 start/stop 烟雾测试。staged 源码增量未新增 MAP、account lifecycle、restricted accounts、departed accounts、bulk quota 或 payer 业务行为。
