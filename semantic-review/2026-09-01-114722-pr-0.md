# MAP 标签写操作收紧与动态 Resource Explorer 区域覆盖

本次修复把所有 MAP 写入口统一收紧到数据库中的当前 admin 身份，为扫描增加中央运行模式的显式确认，并将手工 Resource Explorer 索引区域从固定列表改为实时组织覆盖。前后端确认字符串和新区域 API 契约一致，旧角色 JWT 不能绕过实时角色检查。动态区域的后端重新读取和精确集合校验能阻止客户端漏报或夹带区域，但新增的“区域并集”丢失了账户级启用关系，不能安全驱动按 Root OU 下发的 StackSet。Watch for: **confirmed** — 只在部分账户启用的 opt-in 区域会被当作整个组织的部署区域，且任意并集区域都可被选作聚合区，可能留下没有聚合索引的账户并制造无效 StackSet 实例。

**Verdict**: NEEDS_CHANGES

## High-level view

MAP 写权限现在以数据库当前用户为准，并绑定 JWT 中的 userId 与 username。全部七个 MAP mutation 路由使用严格守卫，扫描还要求后端校验明确的中央模式确认值。

区域读取覆盖 payer 与全部 ACTIVE 成员账户；任一成员查询失败会让请求整体失败。POST `/tag-compliance/re-indexes` 重新计算区域并要求本地区域与服务器结果完全一致，不信任前端缓存。

区域结果只保留组织级并集和每区计数，StackSet 却按 Root OU × Regions 做笛卡尔积部署。这把“某个账户启用了某区”错误提升为“全部成员都应在该区部署”，聚合区校验也只要求至少一个账户启用，而不是所有目标账户都启用。

并发区域请求没有与发起请求时的 payer 绑定。旧请求可以覆盖新 payer 的显示状态；后端重新校验会阻止危险部署，但用户会看到陈旧计数或收到一次可避免的 400。

## 组织区域并集不能表达 StackSet 的账户级目标

`getOrgEnabledRegions` 在 `web/server/tag-compliance.ts:1349-1365` 将所有成员和 payer 的区域压平成并集，仅额外保留每区账户数量。`POST /tag-compliance/re-indexes` 在 `web/server/routes/aws.ts:247-265` 接受并集中的任意区域作为聚合区，并把其余整个并集交给 `deployReIndexes`。

实际下发在 `web/server/tag-compliance.ts:1057-1058` 和 `1084-1085` 使用 Root OU 作为账户目标，并一次提交聚合区或所有本地区域。因此部署集合是“Root OU 中所有成员 × 区域并集”，而不是扫描得到的“每个成员 × 该成员已启用区域”。例如，只有账户 A 启用了 `ap-south-2` 时，本地 StackSet 仍会尝试在组织内每个账户的 `ap-south-2` 创建索引；未 opt-in 的账户会产生失败实例。更严重的是，管理员可把 `ap-south-2` 选为聚合区，未启用该区的其他成员将无法创建聚合索引，形成扫描盲区。该问题为 **confirmed**。

区域发现结果需要保留 `accountId -> regions` 或 `region -> accountIds`，并让每个 StackSet 操作只命中实际启用该区域的成员。若继续使用整 Root OU 的组织目标，聚合区至少必须限制为所有 ACTIVE 成员共同启用的交集；本地 opt-in 区域仍需按账户集合拆分部署，不能仅靠并集或计数。

## 区域请求可以把旧 payer 的结果写回当前表单

`loadEnabledRegions` 在 `web/client/src/pages/TagCompliance.tsx:117` 捕获请求时的 payer，但响应到达后在 `140-143` 无条件更新共享状态；`handleDetect` 在 `201` 又以 fire-and-forget 方式启动它。用户从 payer A 快速切换到 payer B，或连续触发读取时，A 的较慢响应可以最后写回 B 的表单。这是 **confirmed** 的前端竞态。

服务器在 POST 时重新读取 B 的覆盖并执行集合比较，因此风险限于陈旧区域计数、错误的可用选择和一次失败操作，而不是权限绕过。响应写回前核对当前 payer，或使用 AbortController/请求序号丢弃旧响应即可消除。

## MAP 安全路径缺少回归测试

未找到 MAP 专项测试。严格守卫、并集/交集边界、成员查询失败和前端乱序响应都没有自动回归覆盖；这是 **confirmed** 的测试缺口。本次完整 Vite 构建、服务端 TypeScript 编译和目标 diff whitespace 检查均通过，但这些静态验证不能发现账户×区域目标错误。
