# Per-region abort isolation for scheduled region sync

The hotfix gives each of the 17 concurrent region-status calls an independently timed `AbortSignal` while retaining one shared `AccountClient` per account. This removes the listener fan-out that produced `MaxListenersExceededWarning` without serializing requests or changing result mapping. Cleanup remains scoped to its owning request or account, and the patch version moves from 0.10.3 to 0.10.4.

Watch for: **confirmed** — no Critical, High, Medium, or Low findings. The approximately 30-second bound applies to the concurrent region-request phase after credentials are acquired, not to the entire multi-account scheduler run; that scope is unchanged.

**Verdict**: APPROVED

## High-level view

Each `client.send` now receives a distinct signal, so no EventTarget accumulates the 17 SDK abort listeners that crossed Node's default threshold. Reusing the `AccountClient` does not recreate the shared-signal fan-out.

The 17 timers begin within the same short dispatch window under `Promise.allSettled`, keeping request-phase timeout latency near 30 seconds rather than 17 × 30 seconds. Every started request clears its timer, and the client is destroyed after every region worker settles.

Failures still become `{ region, status: 'ERROR' }`; results retain input order and are written once through the existing account-level upsert.

## Per-request abort ownership removes listener accumulation

The changed worker creates one controller per region and passes that signal to exactly one `client.send`. Listener counts are therefore isolated per EventTarget; sharing only the SDK client preserves connection reuse without sharing abort listeners.

## Thirty-second timeout remains parallel, not cumulative

Each worker gets a 30,000 ms timer immediately before its request, so the latest deadline differs only by dispatch and abort-settlement overhead. This is not a hard ceiling for all of `syncRegions`: `assumeToAccount`, five-account batching, and inter-batch delays remain outside that measurement, as they were before the patch.

## Resource and persistence semantics remain account-scoped

The per-request `finally` clears timers after success, rejection, synchronous send failure, or abort. The enclosing `finally` destroys a successfully constructed client only after `Promise.allSettled` has kept it alive for all region workers; moving timer creation after client construction also removes the baseline's timer leak window if construction throws.

API failures and aborts remain `ERROR` records rather than rejected account scans. `Promise.allSettled` preserves region order, and `db.upsertRegionData` remains a single write after the full account result set converges. As before, cleanup ultimately relies on the AWS SDK honoring abort and settling the request promise; the patch introduces no new indefinite-wait path.

## Validation and release marker

The user reports `npm run build` passing, and the scoped `git diff --check` also passed during this review. The release marker is 0.10.4.
