# Empty-organization-safe Resource Explorer StackSet onboarding

The change preserves StackSet deployment intent when an organization has no member accounts: AutoTagger and the Resource Explorer aggregator target the root OU, while every dynamically discovered default local region gets a root `NONE` target. Default regions remain on the auto-deployed local StackSet, and optional regions are isolated in an account-scoped StackSet with AutoDeployment disabled. Completion separates configuration validity from current instance count, and old wait-stage jobs can recreate missing Resource Explorer StackSets. No confirmed High or Medium issue was found in the requested scenarios.

Watch for: no confirmed High/Medium concerns in empty-organization setup, first-account auto-deployment, retained-stack migration, region filtering, repair, or completion semantics.

**Verdict**: APPROVED

## High-level view

An empty organization now records future deployment intent instead of treating zero instances as completion. The aggregator, AutoTagger, and every `opt-in-not-required` local region retain root targets, allowing CloudFormation AutoDeployment to cover the first future member without rerunning onboarding.

Root-wide local deployment is limited to default regions enabled by every active member. Other member-enabled regions use the scoped StackSet with `AutoDeployment=false` and account intersections; legacy broad targets are detached with `RetainStacks=true` before scoped coverage converges.

The wait state checks permission model, exact AutoDeployment setting, required root targets, extra common-local root regions, account-region coverage, and active operations. Missing Resource Explorer StackSets, root targets, and instance gaps are repaired across later polls, while zero expected instances cannot waive the AutoTagger, aggregator, or default-local configuration requirements.

## Empty organization and first-account coverage

`deployReIndexes` handles `memberAccountIds.length === 0` explicitly, creating or verifying the aggregator root target and deriving common local targets from the live `opt-in-not-required` region set. `getOnboardingStackSetStatus` independently derives the same default-local requirements for zero members, so `expectedInstanceCount === 0` cannot produce completion without valid StackSets and root targets. AutoTagger's provision phase also submits its root OU target when the empty organization has no instances, and wait-stage repair restores a missing historical target.

## Optional-region containment and retained migration

A common local region must be both default-enabled and enabled by every active member. Optional regions remain scoped even when all current members have opted in; scoped operations use `AccountFilterType: INTERSECTION`, and both creation and status validation require `AutoDeployment=false`.

Legacy common-local root targets outside the new common set are removed with `RetainStacks=true`. A replacement scoped instance that reports `AlreadyExists` is accepted only after a strict support-role read confirms an `ACTIVE` local index replicating to the chosen aggregator, preserving the retained index without weakening current coverage checks.

## Completion and repair convergence

Completion excludes out-of-scope historical pairs but still blocks on current missing, failed, or pending targets, active operations, invalid permission/AutoDeployment settings, absent required root targets, and extra common-local root regions. Repair performs one corrective action per poll and can create missing aggregator, common-local, or scoped Resource Explorer StackSets before restoring targets and instance gaps.
