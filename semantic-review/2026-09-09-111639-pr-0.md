# Admin-only 排除账户第二轮定向复审

本轮复核 `adminRoleExcludedAccounts` 对控制台、临时 Admin 凭证、角色自愈和组织 StackSet 下发的约束。上一轮三项问题均已闭环：省略 `access` 不再允许排除成员账户进入 `auto` 的 OAAR Admin 回退；残留 `admin-console` 会写为 `partial` 并记录错误；配置中的 payer 归属会通过分页 `ListAccounts` 实时验证后才部署。相关保护没有改变普通成员账户、payer 管理账户、严格 support 会话或独立 Root AssumeRoot 链路。Watch for: 本轮限定范围内无 confirmed 问题；上线前仍需用真实 AWS 账户验证 StackSet 排除和凭证拒绝行为。

**Verdict**: APPROVED

## High-level view

账户页对排除成员账户显式请求 `support`，服务端又在凭证分支前拒绝其 `auto`/`admin` 请求，因此旧前端、省略参数或直接调用 API 都不能进入 `assumeToAccount` 或 OAAR Admin 回退。

角色自愈把排除账户的目标状态定义为 `support=true && admin=false`。残留 `admin-console` 会持久化为 `partial` 并提示删除 StackSet 实例；补建流程只修复 support，不会重建 Admin。

StackSet 脚本使用当前 payer 的 Organizations 凭证分页列出账户，并在任何部署操作前验证 admin-only 排除项。归属不匹配或 Organizations 读取失败都会停止该 payer 的处理。

payer 管理账户仍使用 `role/tool`，普通成员账户保留原有 `auto` 和 Admin 路径，显式 support 仍为严格一级跳，Root 特权操作仍由 payer 发起 `AssumeRoot`。

## 控制台与临时 Admin 凭证形成服务端闭环

`getConsoleSigninUrl` 先识别 payer 管理账户，再对非 payer 排除账户执行 `access !== 'support'` 拒绝。允许的 `support` 分支只调用 `assumeRoleStrict`，失败时不会回退 OAAR 或 `admin-console`。`Accounts.tsx` 的共用 `ConsoleButton` 只为排除账户生成显式 `support` 请求，Root 面板同时隐藏 Admin 临时凭证入口。

`getTempAdminCredentials` 在 payer 特例之后、任何成员 Admin AssumeRole 之前拒绝排除账户，直接请求 `/temp-credentials/:accountId` 也不能利用残留角色；`assumeAdminViaOAAR` 另有同一排除门禁。

## 角色自愈以“Admin 必须不存在”为健康条件

排除账户的 `nowGood` 要求 support 可用且 Admin 不可假设；`adminPolicyViolation` 会写入 `partial` 和 `排除账户仍存在 admin-console` 的 `last_error`，该记录进入角色问题汇总。补建分组仍可修复缺失 support，但不会把排除账户加入 Admin 补建组；既有 Admin 的删除继续由运维显式执行。

## Organizations 归属验证在部署前 fail closed

`validateAdminRoleExcludedAccounts` 使用当前 payer 凭证并持续读取 `NextToken`。任一排除 ID 不在实时 `ListAccounts` 结果中都会使 `handle` 返回失败，后续 StackSet 创建、更新和实例部署均不执行；dry-run、首次创建、自动部署修正和模板刷新共用此前置检查。

## support、payer、Root 与普通成员账户没有回归

payer 管理账户在排除门之前由 role ARN 识别，控制台仍使用 `role/tool`；只读入口继续叠加 `ReadOnlyAccess` session policy，Admin 入口和一小时临时凭证未被拦截。角色同步仍过滤 `_isPayer`。

未排除成员账户继续保留 support 优先、`auto` 回退和显式 Admin 路径。账单导出仍显式使用 `access='support'`。Root 凭证审计、删除 Root MFA、恢复密码和删除 Root access key 继续调用独立 `assumeRoot`，排除策略只关闭 Admin 临时凭证和 Admin 控制台。

## 验证结果与必要运行时检查

`git diff --check` 通过。`npm run build` 完成 Vite 生产构建和 `tsc -p server/tsconfig.json`，覆盖前端、服务端及 StackSet 脚本；仅有既有 vendor chunk 大小警告。

上线前应在真实 AWS 环境验证：

- 排除成员账户省略 `access` 和传 `access=admin` 均被拒绝，`access=support` 获得 support 会话，临时 Admin 凭证返回 409。
- 同一排除账户的 Root 审计及获准的 AssumeRoot 操作仍可用。
- 残留 `admin-console` 时 probe-only 结果为 `partial` 且有对应 `last_error`；删除 Admin StackSet 实例后变为 `ok`。
- 正确 payer 的 Admin StackSet `--dry-run` 通过归属校验；故意错误 payer 在任何 StackSet 操作前失败。
- 抽样未排除成员账户和 payer 管理账户，确认普通 `auto`/Admin 与 payer `role/tool` 入口仍可用。
