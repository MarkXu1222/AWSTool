# EventBus 分页已闭合，Quick Setup provider 信任仍可漂移

最新版本正确修复了 `ListEventBuses` 分页：inventory 与 CloudFormation absence probe 共用显式 `NextToken` 循环，重复 token 会抛错并使扫描失败。`DescribeStackInstance` 的请求与响应字段也与 botocore 1.42.68 模型一致，StackSet 名称、StackId、状态、账户和区域的关系均被核对，API 错误不会放行。当前 Quick Setup 门禁仍只把 provider 的部署包 hash、Runtime 和 Handler 当作运行身份，未覆盖可独立漂移的 Lambda Layers、环境变量和执行角色，并且扫描后到 `DeleteStack` 前不复核可变的未限定函数。nuke 的 issue/gap 零写门禁和 Python 3.9 兼容性复查通过。

Watch for: **[High][confirmed]** provider 配置漂移可在保持 allowlisted `CodeSha256` 的同时改变删除回调实际执行内容和权限；**[High][confirmed]** scanner 验证与 `DeleteStack` 之间存在未限定 `$LATEST` provider 的 TOCTOU；**[Medium][confirmed]** 这些破坏性不变量仍无仓库级回归测试；**[Low][confirmed]** processed template 仍只接受 JSON。

## High-level view

EventBridge 上一轮 High 已关闭。`list_event_bus_names()` 消费所有返回 token，inventory 与 absence probe 使用同一结果；重复 token、列表调用错误或任一 `DescribeRule` 非 NotFound 都会进入 scanner issue，而不是生成 absence proof。

StackSet API shape 与 lineage 比较成立。`StackSetName` 作为请求选择器定位 StackSet，响应中的 `StackId`、`CURRENT`、`Account` 和 `Region` 再绑定当前 stack；空响应、字段不匹配和 API 异常都会 fail closed。

**[High][confirmed]** Quick Setup provider 的可信身份仍不完整。Lambda `CodeSha256` 不覆盖 Layers、Environment 或 Role，而 StackSet `CURRENT` 不证明底层函数当前无 drift；同一个 allowlisted zip 可以在恶意 layer/wrapper 或更高权限执行角色下运行。

**[High][confirmed]** provider token 是 `Fn::GetAtt` 得到的未限定函数 ARN。扫描记录 trusted marker 后，删除器只提交 `DeleteStack`，函数代码或配置可在两者之间变化；需要不可变 published version 的限定 ARN，或继续把该 custom resource 作为阻断项。

issue/gap 检查位于 deletable 构造与 `delete_round()` 之前。离线 issue 与 coverage-gap trap 均得到 0 次删除调用；botocore 模型检查和 Python 3.9 feature AST 也通过，且复审未读取 `config.json`/`data/db.json`、未调用 AWS。

## EventBus 枚举与 absence proof 已共用完整分页

`list_event_bus_names()` 显式把响应 `NextToken` 带入下一次 `ListEventBuses`，并维护 token 集合检测循环（`scripts/cleanup.py:965-987`）。`_scan_eventbridge()` 与 `reference_confirmed_absent()` 都调用该函数（`scripts/cleanup.py:1383,1744`），消除了上一版 scanner 与 absence proof 同时漏掉第二页 bus 的路径。

离线三页 fake 返回 `bus-a/b/c` 加 default，请求依次为无 token、`t1`、`t2`；重复返回 `t1` 时抛出 `CleanupError`。botocore 1.42.68 模型确认 `ListEventBuses` 输入/输出均使用 `NextToken`。列表错误、重复 token 或 `DescribeRule` 的非 NotFound ClientError 会使 CloudFormation scanner 失败，未发现新的 fail-open。

## StackSet 字段匹配正确，但 provider 配置不在身份边界内

`DescribeStackInstance` 的参数 `StackSetName`、`StackInstanceAccount`、`StackInstanceRegion` 均存在于固定 botocore 模型；响应确有 `StackId`、`Status`、`Account`、`Region`，且 `CURRENT` 是有效状态。代码通过请求选择按 definition ID 构造的 StackSet，再要求返回 StackId 等于当前 stack ARN、账户与区域相同并核对 stack name 前缀（`scripts/cleanup.py:1507-1521`）。该调用不分页；缺字段或异常会使 `_collect()` 产生 failed coverage record。

**[High][confirmed]** provider 校验只读取 `Configuration.CodeSha256`、`Runtime` 和 `Handler`（`scripts/cleanup.py:1531-1554`）。`UpdateFunctionConfiguration` 可以在不改变 deployment package `CodeSha256` 的情况下改变 Layers、Environment 和 Role；例如 layer 配合 `AWS_LAMBDA_EXEC_WRAPPER` 可在 handler 前运行 layer 内容。out-of-band drift 不必把 StackSet instance 的 `Status` 从 `CURRENT` 改掉，因此模板 hash、tags、StackSet lineage 与这三个字段可以全部通过，而删除回调实际代码路径或权限已经变化。

目标账户管理员也能构造同名 self-managed StackSet、普通 tags 和相同模板；**[High][confirmed]** 精确 allowlisted 代码本可把风险收敛到行为身份，但当前未覆盖函数配置漂移，lineage 不能补上该缺口。应校验 provider 的完整执行配置和不可变 layer 版本；新鲜 drift 状态可作附加证据，但不能替代配置身份。

## 未限定 Lambda token 留下 scan-to-delete TOCTOU

**[High][confirmed]** custom resource 的 `ServiceToken` 被要求是 `Fn::GetAtt SSMLifecycleOperatorLambda.Arn`，这是未限定函数 ARN；allowlisted `CodeSha256` 在 scanner 阶段读取。后续 `_delete_CloudFormationStack()` 不再读取 provider，只直接调用 `DeleteStack`（`scripts/cleanup.py:2600-2604`）。完整账户扫描和 deletion ordering 形成窗口，期间有 Lambda 更新权限的 actor 或自动化能替换 `$LATEST` 代码/配置，CloudFormation 删除随后调用变化后的 provider。

删除前再次 `GetFunction` 只能缩短、不能消除竞态。安全闭合需要 custom resource token 指向配置与代码均不可变的 published Lambda version，并校验该限定版本；如果受信 Quick Setup 模板只能使用未限定 ARN，则该 custom resource 应继续产生 blocking issue。

## 破坏性门禁仍正确但没有持久回归保护

`command_nuke()` 每轮在构造 deletable 和调用 `delete_round()` 前检查 `inventory.issues` 与 `coverage_complete`（`scripts/cleanup.py:3385-3401`），最终完成条件再次要求无 issue 且 coverage complete。离线分别注入 scanner issue 和 coverage gap，两次都以 `blocking_scan_or_coverage_issues` 停止、actions 为空、`delete_round_calls=0`。

**[Medium][confirmed]** 工作区没有 cleanup 专用测试。应把多页/重复 token、StackInstance shape mismatch、provider 配置漂移、scan-to-delete 变更以及 issue/gap 零写 trap 固化为离线测试。

Python 3.9 feature AST 解析整个脚本成功，当前环境 boto3 为固定的 1.42.68；未发现 Python 3.10+ 专属语法门槛。

## Processed template 的 JSON-only 阻断仍未处理

**[Low][confirmed]** `GetTemplate(TemplateStage="Processed")` 返回字符串时仍只调用 `json.loads`。CloudFormation 允许合法 YAML template body；遇到 YAML 会 fail closed 并阻断清理，不会触发写入。应使用安全 YAML parser，或以可验证约束明确受信 Quick Setup 模板必为 JSON。
