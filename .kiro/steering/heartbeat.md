# 心跳汇报机制

## 规则说明

在所有分析、开发、修改、测试任务执行过程中，必须按照以下规则输出心跳状态，确保用户始终了解当前工作进展。

## 触发条件

以下情况必须输出一次心跳状态：

1. **每完成一个步骤** — 包括但不限于：读取文件、分析代码、修改文件、运行命令、执行测试
2. **长时间操作进行中** — 如果某一步预计或实际耗时较长，先输出当前状态再继续
3. **遇到阻塞** — 无法继续时必须立即输出状态并明确说明原因
4. **任务开始时** — 接到任务后第一步输出初始状态
5. **任务完成时** — 所有工作结束后输出最终状态

## 心跳状态格式

```
心跳状态：
- 当前阶段：[分析/设计/实现/测试/完成]
- 当前进度：[X/Y 或百分比描述]
- 正在处理：[当前正在做的具体事项]
- 已完成：[已完成的步骤列表]
- 下一步：[接下来计划做的事项]
- 是否遇到阻塞：[无 / 有 — 具体原因]
```

## 关键原则

- **不要长时间沉默** — 宁可多汇报一次，也不要让用户等待时无法判断进展
- **明确卡住原因** — 如果无法继续，必须说明具体原因（缺少信息、权限不足、依赖未满足等），不要静默等待
- **状态要具体** — 避免模糊描述，尽量说明具体文件名、函数名、操作内容
- **保持简洁** — 心跳状态是辅助信息，不要喧宾夺主，保持简洁明了
